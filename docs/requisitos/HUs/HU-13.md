# HU-13 – Creación de reservas

**Módulo:** reservas · **Rol:** usuario

## Historia de usuario

> Como usuario con un vehículo registrado, quiero elegir un parqueadero y un rango de fecha y hora para reservar un espacio compatible, para tener un cupo confirmado cuando llegue.

## Criterios de aceptación

- [ ] Selecciono parqueadero, vehículo, fecha y hora de inicio y fin; el backend asigna un espacio compatible disponible.
- [ ] El tipo de vehículo debe corresponder al de la zona; si no, la reserva se rechaza con un mensaje claro.
- [ ] No se permiten parqueaderos sin horario configurado, espacios inactivos ni reservas con horario cruzado; el mensaje indica el motivo.
- [ ] Un mismo vehículo no puede tener dos reservas con horarios cruzados.
- [ ] La hora de inicio debe ser futura y la de fin posterior a la de inicio.
- [ ] La reserva se crea confirmada y el espacio queda bloqueado solo durante ese intervalo.
- [ ] La restricción de no solapamiento se aplica también en la base de datos ante solicitudes simultáneas.
- [ ] Al crear la reserva se muestra una confirmación con el detalle.

## Dependencias

[HU-04](HU-04.md), [HU-08](HU-08.md), [HU-10](HU-10.md), [HU-12](HU-12.md).

## Pendientes por definir / notas técnicas

No se aplica un máximo de 24 horas, conforme a la decisión aprobada. La anticipación mínima y el
pago previo siguen pendientes de definición.

## Cambio respecto a la historia original

La asignación del espacio se realiza en el servidor para evitar que dos usuarios elijan el mismo
cupo; la disponibilidad del martes no afecta el miércoles si los rangos no se solapan.

Absorbe la HU-14 (validación de compatibilidad), que era una regla y no una historia. Se agregan
reglas de tiempo, concurrencia y confirmación.
